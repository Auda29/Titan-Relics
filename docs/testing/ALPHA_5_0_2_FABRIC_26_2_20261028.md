# Fabric 26.2 Alpha 5.0.2 verification, 28 October 2026

Artifact: `relics-0.1.0-alpha.5.0.2+mc26.2.jar`.
SHA-256: `c7165ec0ad298acc18337e17c2b1baa42d2b7d18b860ca989108d09631bf6af9`.

[Machine-readable evidence](alpha5-0-2-fabric-26.2-20261028-evidence.json)
binds the final JAR to the native server checks and archive comparison.

## Change

The primary recipe implementation now maps the serializer's constant Boolean
variant to/from independent recipe instances. The old published Fabric 26.2
Alpha 5.0 JAR fails the new independent-instance network check with the same
`Can't encode MaintenanceRecipe` exception. The modern normal synchronization
packet carries properties/displays, so this does not assert that the old 26.2
client exhibited the 1.21.1 join-time disconnect.

Archive comparison against the original release finds exactly two changed
entries: `fabric.mod.json` and `MaintenanceRecipe.class`. All other classes and
resources, all 40 templates and the frozen selection manifests are identical.
The new primary JAR contains 92 Java 25 runtime classes and no validation code.
Existing same-target Alpha 5 worlds retain their generation fingerprint/items.

The redundant NeoForge-only codec substitution is removed because the primary
source now supplies it. Rebuilding Fabric 1.21.1, NeoForge 1.21.1 and NeoForge
26.2 must reproduce their already published Alpha 5.0.2 JARs byte-for-byte.
Those release tags and downloads are preserved.

## Validation

`tools/build_fabric26_checks.py` adapts the common recipe checks to the modern
Fabric API and compiles them against the actual player JAR. Its validation mod
is separate from production. `tools/test_alpha5_port_server.py` now also supports
Fabric 26.2 using the checksum-verified portable dependency cache.

The native suite runs the 98 recipe network assertions on both server starts:
independent instances, holder IDs, wrong-variant rejection, fully consumed
buffers, complete update and recipe-book packets, display IDs/flags/dimensions,
and decoded crafting with input/component preservation.

It also checks core processing/menu state and smithing, native Trial/Vault phases
and event packets, personal physical rewards, immediate key payment, original
outstanding drops after restart, magnet pickup budgets in either hand, the 51
80-block Tree-aura cases and shared natural animal population caps.

CI builds and runs this suite against the primary release artifact, replacing
the narrower standalone Tree-animal invocation while retaining its assertions.
The original standalone tool remains available for focused checks.

Reproduction after preparing the frozen resources and Java dependencies:

```shell
python tools/build.py --skip-generation --java-home /path/to/jdk25
python tools/build_fabric26_checks.py --java-home /path/to/jdk25 --artifact dist/relics-0.1.0-alpha.5.0.2+mc26.2.jar
python tools/test_alpha5_port_server.py --loader fabric --minecraft 26.2 --accept-eula --java /path/to/java25 --artifact dist/relics-0.1.0-alpha.5.0.2+mc26.2.jar --test-mod build/fabric26-checks/relics-alpha5-port-checks+mc26.2.jar --suite
```

Server checks use simulated players and actual encoded packet bytes. They do
not claim a new graphical-client or full TerraVista modpack acceptance. No
launcher profile or player save is opened or modified by these checks.

The separate staged Git export builds byte-identical player and validation JARs.
Nineteen focused Python resource/storage/compression/layout/packaging checks,
677 headless gameplay assertions and 63 static mixin contracts pass. All three
previously published port JARs were rebuilt with their original SHA-256 values.

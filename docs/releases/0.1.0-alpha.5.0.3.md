# Relic Mod Alpha 5.0.3

Fixes false frozen-worldgen mismatches when reopening a world. World-generation
signatures now sort JSON object keys before hashing, while preserving array
order and actual settings. The fix is included in all four downloads:

| Minecraft | Loader | Java |
|---|---|---|
| 26.2 | Fabric | 25+ |
| 26.2 | NeoForge | 25+ |
| 1.21.1 | Fabric | 21+ |
| 1.21.1 | NeoForge | 21+ |

Install one matching JAR with its Fabric/NeoForge and Lithostitched dependencies.
Fabric also needs the matching Fabric API. Dependencies are installed separately.

Existing legacy planning snapshots migrate automatically when their old hash
matches exactly. Unmatched legacy snapshots require a reviewed, one-time
transition tied to the old and current hashes. The original plan is backed up
before migration; destinations and gameplay receipts are preserved. A complete
save backup is still recommended. Do not downgrade a migrated world to 5.0.2.

[Recovery procedure and verified Living World example](https://github.com/Auda29/Relic-Mod/blob/main/docs/testing/ALPHA_5_0_3_WORLD_RELOAD_20261028.md)

The full Living World modpack was tested on an isolated save copy with an actual
Minecraft client: load, save and another launch without the recovery argument
passed. All four native loader suites passed startup/restart, recipe packets,
personal Trial/Vault rewards, magnet wear and Tree effects. This is targeted
reload coverage, not certification of every modpack interaction.

Compare your download with the attached `SHA256SUMS.txt`.
